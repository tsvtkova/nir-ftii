# Пошаговая инструкция: как разместить систему на GitHub

Эта инструкция рассчитана на человека, который раньше не работал с GitHub.

## Вариант 1 — самый простой: через сайт GitHub

### Шаг 1. Создайте аккаунт

Откройте GitHub и войдите в свой аккаунт.

Если аккаунта нет — зарегистрируйтесь.

### Шаг 2. Создайте новый репозиторий

На GitHub нажмите:

`+` → `New repository`

Рекомендуемые настройки:

- Repository name: `nir-assessment`
- Description: `Система оценивания НИР магистров`
- Visibility: `Private` или `Public` — в зависимости от того, кому вы хотите открыть материалы.
- Не ставьте галочку создания README, потому что README уже есть в нашем пакете.

Нажмите `Create repository`.

### Шаг 3. Распакуйте ZIP

Распакуйте скачанный архив на компьютер.

Внутри должна находиться папка с файлами:

`README.md`

`docs/`

`rubrics/`

`artifacts/`

`commission/`

`templates/`

`scripts/`

### Шаг 4. Загрузите файлы

Откройте созданный репозиторий.

Нажмите:

`Add file` → `Upload files`

Перетащите ВСЕ файлы и папки из распакованной папки в окно браузера.

GitHub должен показать список добавляемых файлов.

Внизу страницы найдите поле commit message.

Напишите:

`Первоначальная версия системы оценивания НИР`

Нажмите:

`Commit changes`

После этого система будет загружена в GitHub.

# Вариант 2 — GitHub Desktop

Этот вариант удобнее, если вы планируете регулярно обновлять материалы.

## Шаг 1. Установите GitHub Desktop

Установите приложение GitHub Desktop и войдите в свой GitHub-аккаунт.

## Шаг 2. Клонируйте репозиторий

В GitHub Desktop выберите:

`File` → `Clone repository`

Выберите созданный репозиторий.

Программа скачает его на компьютер.

## Шаг 3. Скопируйте файлы

Скопируйте содержимое нашего пакета в папку репозитория.

Не удаляйте папку `.git`, если она уже появилась.

## Шаг 4. Проверьте изменения

Откройте GitHub Desktop.

Слева появится список изменённых файлов.

В поле Summary напишите:

`Добавлена система оценивания НИР`

Нажмите:

`Commit to main`

Затем:

`Push origin`

Теперь изменения опубликованы на GitHub.

# Как пользоваться репозиторием после создания

Вам не нужно каждый раз заново загружать весь проект.

Например, вы изменили:

`rubrics/GENERAL_MATRIX.md`

После этого:

1. откройте GitHub Desktop;
2. проверьте список изменений;
3. напишите описание изменения;
4. нажмите `Commit`;
5. нажмите `Push origin`.

GitHub будет хранить историю изменений.

# Как лучше организовать работу

Не рекомендую складывать всё в один огромный README.

Лучше использовать два уровня документации.

## Уровень 1 — для комиссии

Человек открывает репозиторий и сразу видит:

- что это за система;
- где быстрый чек-лист;
- где общая матрица;
- где критерии конкретного типа проекта.

Для этого используются:

`commission/`

и

`rubrics/`

## Уровень 2 — полная методика

Здесь находятся подробные формулировки критериев, ограничения максимальной оценки, требования к артефактам и пояснения.

Для этого используются:

`docs/`

# Как обновлять критерии

Если критерии изменились:

1. меняете соответствующий `.md` файл;
2. сохраняете;
3. делаете commit;
4. отправляете изменения на GitHub.

Например:

`docs/FULL_CRITERIA.md`

Можно хранить версии через Git.

Например:

`v1.0 — первая версия`

`v1.1 — уточнены критерии 5А`

`v2.0 — обновлена матрица`

---

# Важное правило

GitHub — это не место, где нужно хранить личные данные студентов.

Не размещайте:

- оценки конкретных студентов;
- персональные данные;
- закрытые рецензии;
- API-ключи;
- пароли;
- ссылки с приватными токенами.

Методические материалы можно хранить отдельно от персональных данных.
